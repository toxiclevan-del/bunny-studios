NOMAD Shop Core — USER MANUAL

Version 0.2.0-rc.4 · English primary edition

A — Getting started

NOMAD is a framework-independent UGUI shop, catalog editor, EN/CZ localization and renderer-only interactive 3D viewer. It contains Runtime, Editor, original demonstration models/materials/prefabs, a demo scene and this documentation. It does not contain your game's equipment system, persistence, NPC AI, a second production wallet or multiplayer authority.

Only Unity 6000.6.3f1 + URP 17.6.0, Unity UI 2.6.0, Input System 1.20.0 are tested. Unity physics/animation modules are dependencies for isolated preview scenes and skinned mesh baking. The demo uses the new Input System and requires Input System Package (New) or Both in Active Input Handling. Built-in/HDRP, mobile/controller navigation, every aspect ratio and other Unity versions are not certified by these tests. Demo materials are URP/Lit; you must configure an active URP asset in Graphics/Quality.

Follow Quick Start for Package Manager preparation, custom package import, the exact demo scene path, Play, purchase and creation of your own catalog/scene copy. Runtime UI is built at Start: a black Game view outside Play in the minimal demo is normal. A successful initial purchase is 110 → 90 credits and one owned item, not just an animation.

B — NOMAD Shop Editor

Open Tools > NOMAD > Shop Editor. The complete field reference and procedures cover catalog creation/selection, category rename/reorder/hide/remove, item creation/removal/assignment, IDs, currency, stock/limits, icons, prefabs, framing, language entries, save and validation. Expand the definition foldout (stable ID or Element), localized text and Preview foldouts to see their fields. Most fields are Unity serialized properties; there are no hidden theme designers, price calculators or gameplay item generators.

C — Shop UI and interaction

ShopView.Create(parent, font) creates the overlay canvas; Open(catalog, backend) displays the first visible category. The demo supplies both automatically. Visible category tabs scroll horizontally, items vertically. Select an item to show its translated name/description, live preview, Stats, total delivery price and availability. ALL ITEMS shows every item in the current category; MY EQUIPMENT filters that category to owned items. It does not show an unrelated full game inventory. Unavailable items stay listed but cannot be purchased. Empty categories show a deliberate empty state.

BUY ITEM asks the backend to purchase; confirmation appears in the lower feedback line, current balance/ownership refresh, and the button reflects funds/capacity/stock/limit checks. Each delivery costs Price and grants Quantity units. EQUIP ITEM calls the equipment adapter separately when Equippable and owned. Validation may fail with NOT ENOUGH FUNDS, INVENTORY FULL, LOCKED, SOLD OUT, ALREADY OWNED or UNAVAILABLE. Delivery failures with a correct adapter roll back; this is not an external payment checkout.

The UI polls its backend roughly every 0.15 seconds and rebuilds changed rows. It is not a live catalog-authoring tool: close/reopen after structural catalog changes. ESC/F are NomadDemo shortcuts; ShopView alone does not bind them. Close calls CloseRequested, which your host must wire to its actual close/cleanup method. The demo manages cursor visibility/lock only. NPC detection, interaction key/action, input suppression, reticle and pause policy belong to your integration. Use the API guide and modal checklist; never leave movement/fire reading direct input behind an open shop.

D — 3D item viewer

In the item Preview foldout assign a Project prefab; for a first test use Assets/NomadShop/Demos/Prefabs/Nomad_FieldFlask.prefab. Use mesh renderers with valid mesh/material data or a SkinnedMeshRenderer. Apply source transforms and put the model near a sensible pivot in your modeling tool; preserve its game prefab and adjust Preview.Rotation/Scale for the viewer. A simple render-only preview prefab is recommended even though gameplay scripts are not executed.

The source is never instantiated. Core copies mesh/material render data; skinned meshes bake the supplied pose. It does not play animations or copy colliders, rigidbodies, weapons, particles, scripts or audio. A particle-only prefab has no compatible model; Icon is used if assigned. Disabled renderers/inactive render objects may be omitted. Unsupported materials remain unsupported: preview isolation cannot convert pipelines or execute mesh-generation scripts.

An orthographic Preview Camera and three shadowless spot lights live on a distant stage in a separate local-physics scene. A 1024×528 RenderTexture (2× AA by default) feeds a raycast-enabled RawImage. Catalog.PreviewLayer must be unused by gameplay; existing game cameras lease exclusion of that layer and release it on close, preserving other bits. Cameras created after preview opens require your integration to respect that reserved layer too. Do not change global collision layers for this feature.

Bounds are normalized and fitted to projected size: source world dimensions do not directly set displayed size. Preview.Scale controls relative fill (0.2–1), CameraSize is a minimum frame size, TargetOffset is a bounded look-at offset, Rotation is Euler degrees. The camera expands to avoid clipping and contracts smoothly. See all preview units/ranges. For a sideways item, first adjust Rotation outside Play, not its game prefab; try Y=25 then X/Z only as needed.

Hold left mouse over the image and drag horizontally for yaw, vertically for pitch (clamped to ±65°). Release holds for 1.75 seconds then resumes auto rotation from the current view. Wheel changes bounded zoom; RESET VIEW resets yaw/pitch/zoom to the initial configuration, not the catalog data. AutoRotateSpeed 0 stops automatic turning. ResumeDelay, DragSensitivity and TextureWidth/Height are runtime component fields/API, not dedicated catalog editor controls; custom code may set them before building the next preview. Language changes retain the current model/RenderTexture and rotation.

No model: check Preview.Prefab, compatible enabled meshes, materials, Icon and Preview.LastError. Close releases the RT/model and disables stage camera/lights; final view destruction unloads the stage scene. This is not a live weapon simulation. See troubleshooting.

E — Currency and inventory integration

Read Integration for exact IShopBackend/IShopWallet/IShopInventory/IShopPurchaseRule contracts, licensed-package examples, transaction verification, rollback limits, request IDs, service ownership and save responsibilities. A matching CurrencyID and real inventory Count are mandatory. Demo state resets after Play; it is not a persistent game inventory. Metadata does not deliver actual weapons without a game adapter.

F — Localization

Content strings (Title, Vendor, Currency; category Name; item Name, Description, Requirements; stat Label) are LocalizedText. Expand one in the editor. Language code en holds English; cs holds Czech. The runtime button cycles catalog.Languages in order. Set catalog.DefaultLanguage for NomadDemo, or view.Language before Open / view.SetLanguage(code) during your custom session. The editor Czech toggle only changes authoring labels. A locale switch does not rebuild the preview model.

To translate UI phrases, select Assets/NomadShop/Demos/NomadUILocalization.asset in Project/Inspector. Expand Messages, each element's Text and language entries. Keep each ID exactly unchanged, including spaces: these are English source phrase keys, not purchase result codes. For example ID BUY ITEM has English and Czech values; ID Purchase completed. Item delivered. supplies the success sentence. Create a separate table via Tools > NOMAD > Create UI Localization, save outside the shipped demo and assign it to catalog.Localization if you need independent text.

For a third language, add de to catalog.Languages, then + Add language / Přidat jazyk on every content field and UI-table Text; replace the new xx code with de and supply text. Make codes unique and exact, and translate the 27 UI entries as well as your content. If desired set DefaultLanguage to de and test the entire interface. The language button uses uppercase codes (CZ for cs); it is not a language-name database. Number strings/stats are not automatically culture-formatted.

Fallback: a missing or empty selected-language value falls back to the English entry, not the next language or DefaultLanguage. If English is also absent it returns empty. A missing UI phrase ID/table falls back to built-in EN/CZ; an existing phrase without a third-language translation uses its English entry. Keep English complete. Duplicate language entries use the first matching code and are not detected by catalog validation. Missing glyphs require a font you are licensed to use.

G — Customization and multiple shops

Without code: catalogs, category names/order/visibility, item texts, prices, quantities, delivery limits/stock, icons, stats and preview prefab/framing/rotation/zoom. Configure distinct catalogs for merchants. One catalog supports one currency key; currency display text is separate from the wallet identifier. Different currencies require matching wallet/backend routing, not just a label change.

With code: colors/layout are in ShopView.Build and helper methods/constants; there is no no-code theme/layout editor in this release. Create a maintained source modification or your own view using IShopBackend. ShopView.Create(parent, licensedFont) supplies typography at creation; the default is Unity's built-in LegacyRuntime.ttf, not a bundled third-party font. Longer translations/stat lists can require layout adjustment. Test with your intended resolutions and languages.

Gameplay delivery/equip, unlocks, NPC terminals, input/pause policy, save/load, cross-merchant shared services and online authority require integration. Reserve preview layer consistently across views. Two independent views may preview simultaneously; RT/light costs scale with visible viewers. Reuse one backend for shared customer resources and distinct catalog IDs for merchant history. Do not persist only the wallet and assume stock/history also persist.

H — Troubleshooting and support evidence

Troubleshooting maps symptoms to exact checks. Reproduce in a copy of the independent demo before investigating a game adapter. Record Unity/package versions, catalog validation errors, selected item ID, backend result code and Preview.LastError. Never include passwords, account identifiers or unrelated game assets in a support report.
