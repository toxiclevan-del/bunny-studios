Instalace a kontrola závislostí — RC.4

INTEGRACE — měna, inventář a vlastnictví vstupů

Zvolte jednu transakční hranici

ShopView závisí na IShopBackend. Buď jej implementujte nad svou autoritativní transakční službou, nebo vytvořte new ShopTransactions(wallet, inventory, optionalRules), což IShopBackend implementuje. Nespouštějte dvě ekonomické služby nad stejnými prostředky. Používejte jednu službu pro zákazníka/sdílenou peněženku a inventář; předejte ji více obchodům. Rozdílná ID katalogů oddělují historii obchodníků; ID předmětů určují jednotky inventáře napříč katalogy.

Jde o synchronní lokální rozhraní na hlavním vlákně, ne asynchronní síťová volání. ShopResult je readonly struct s bool Success a string Code. Kódy zahrnují ready, unavailable, invalid, locked, owned, soldout, full, funds, duplicate, purchased, rollback, equipped. ShopView.Message známé kódy překládá; vlastní kódy skončí jako NEDOSTUPNÉ, pokud zobrazení nerozšíříte.

Průběh transakce a hranice obnovy

Purchase odmítá vnořené volání, prázdné ID požadavku a již úspěšná ID. Validate kontroluje skutečný objekt vrácený catalog.Find(ID), Available, zásoby, kladnou cenu/množství, shodu měny, pravidla, limity dodávek služby, kapacitu a prostředky. Předávejte catalog.Find(id), ne nesouvisející kopii se stejným ID.

Core zachytí inventář a původní počty/zůstatek, odečte měnu, ověří přesný odpočet, doručí a ověří zvýšení Count o Quantity. Teprve pak zvýší historii úspěšných dodávek a zaznamená ID požadavku. Při selhání doručení volá Restore a Refund, vrací rollback. Adaptéry nesmějí vyhazovat výjimky při Restore/Refund, provádět nevratné herní akce, ukládat uprostřed ani vracet false po změně peněženky. Core neumí opravit vnější vedlejší účinky chybného adaptéru. Equip je samostatná operace bez nákupního snímku/rollback obalu.

UI vytváří nové ID pro každý zamýšlený klik. Při opakování téže operace použijte původní ID, pro další nákup nové. Pamatují se jen úspěšná ID po dobu života služby. Neúspěch lze zopakovat. Zavření/otevření UI historii neresetuje, pokud službu zachováte. Nový ShopTransactions resetuje historii i deduplikaci; nejde o trvalou nebo meziprocesovou idempotenci. Kandidát nemá veřejné API importu/exportu historie. Trvalé zásoby, limity účtu či online autoritu řešte vlastním IShopBackend nad trvalým transakčním úložištěm; samotné ukládání peněženky nezachovává všechny limity.

Stock omezuje dodávky, není globální měnitelná zásoba sdílená mezi instancemi služby. MaxPurchases počítá dodávky, ne kusy. Katalogy jsou definice: neodečítejte jejich Stock jako náhradu hráčova uloženého stavu. Peněženku, inventář, historii/zásoby a potvrzená ID ukládejte společně po úspěchu. Core neukládá na disk, nerezervuje vzdálené prostředky, neřeší pád procesu ani serverovou autoritu.

Implementační příklady jsou součástí licencovaného balíčku. Veřejný návod popisuje API a integrační postup.

Zapojení příkladu a interakce

V samostatné scéně přidejte prázdný Customer s CustomerStore a CustomerShopHost. Hostu přiřaďte store a platný katalog; store.currencyID musí odpovídat catalog.CurrencyID. Přidejte právě jeden EventSystem s InputSystemUIInputModule a UI akcemi (GameObject > UI > Event System; při použití pouze nového Input System nahraďte starý StandaloneInputModule). Pro svět přidejte hlavní kameru. Core vytváří canvas/viewer, nikoli EventSystem; automatická příprava NomadDemo je pouze pro demo.

Vytvořte běžné Unity UI Button a v OnClick přiřaďte CustomerShopHost.Open. Po Start klikněte v Play: obchod se otevře a BUY ITEM používá výukový adaptér. Zavírací tlačítko přes CloseRequested volá host.Close. Stejné Open může volat interakce NPC po kontrole identity hráče, vzdálenosti, dohledu a dostupnosti obchodníka. Host záměrně nezavádí univerzální klávesu ani detektor NPC. Při použití asmdef musí vaše sestavení odkazovat na Nomad.Shop.Runtime a použité moduly Unity; ukázky nepotřebují demo assembly.

Hranice vstupů: onOpened/onClosed propojte se stávajícím vlastníkem modálního režimu hry, ne s bezpodmínečným zapni vše/vypni vše. Tento vlastník musí zachytit původní pohyb, střelbu, schopnosti, interakce, zaměřovač, kurzor a action mapy; pozastavit pouze herní vstupy se zachováním UI Point/Click/Scroll a obnovit zachycený stav při zavření/smrti/odchodu. Již pozastavený ovladač musí zůstat pozastavený. Nevypínejte UI action mapu ani celý InputSystem. Ukázka řeší pouze svůj kurzor a vyvolává události; bez posluchačů neblokuje postavu. Dodané demo obdobně řeší kurzor a ESC/F, nikoli produkční vstupy. Nekombinujte NomadDemo a tohoto hosta jako dva soupeřící vlastníky obchodu.

Ukázka vytváří jednu službu při Start. Pro více obchodníků přesuňte její vlastnictví do svého správce relace hráče a do pohledů předávejte stejný backend; nevytvářejte službu pro každého obchodníka sdílejícího store. Před finálním zničením zavřete UI; při zániku scény zničte view, aby se uvolnila preview scéna. Vlastní správce musí řešit i smrt hráče, odstranění obchodníka, přerušené interakce a deaktivaci objektů.

Použití API a omezení

ShopView.Create(parent, optionalFont) sestaví UI. Před Open nastavte Language, přiřaďte CloseRequested, pak Open(catalog, backend). Za běhu SetLanguage("cs") obnoví překlady, SelectCategory(categoryID) volejte před SelectItem(itemID) a Close() uvolní náhled. Visible, Selected, CategoryID, Preview poskytují stav. BuyButton, EquipButton, CloseButton, ResetButton, LanguageButton, CategoryButtons a ItemButtons jsou runtime ovládání, ne serializované sloty pro úpravu scene prefabu.

Datové GameplayItem, EquipmentSlot, Rarity, Requirements a Level neimplementují zbraně, brnění, schopnosti ani postup. Available zapínejte až při podporovaném doručení. Pravidla se vyhodnocují před odečtem; pokud je poskytovatel přítomen, musí sám kontrolovat všechna potřebná odemčení. Neprázdné UnlockID bez poskytovatele vrací locked. Funkční náhled není důkaz herní integrace.
