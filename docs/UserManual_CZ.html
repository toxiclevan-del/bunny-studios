Instalace a kontrola závislostí — RC.4

NOMAD Shop Core — UŽIVATELSKÝ NÁVOD

Verze 0.2.0-rc.4 · Úplný český překlad

A — Začínáme

NOMAD je UGUI obchod nezávislý na herním frameworku, editor katalogů, EN/CZ lokalizace a interaktivní 3D viewer kopírující pouze vykreslovaná data. Obsahuje Runtime, Editor, vlastní ukázkové modely/materiály/prefaby, demo scénu a dokumentaci. Neobsahuje vybavovací systém vaší hry, ukládání, AI NPC, druhou produkční peněženku ani multiplayerovou autoritu.

Otestována je pouze kombinace Unity 6000.6.3f1, URP 17.6.0, Unity UI 2.6.0, Input System 1.20.0. Moduly fyziky/animace jsou potřeba pro izolovanou preview scénu a baking skinned meshů. Demo vyžaduje Input System Package (New) nebo Both v Active Input Handling. Built-in/HDRP, mobilní/ovladačová navigace, všechny poměry stran ani jiné Unity verze nejsou těmito testy certifikovány. Demo materiály používají URP/Lit; v Graphics/Quality musí být aktivní URP asset.

Postup přípravy Package Manageru, importu custom package, přesnou cestu dema, Play, první nákup i vlastní katalog/kopii scény obsahuje rychlý start. Runtime UI vzniká při Start: černý Game pohled mimo Play je v minimálním demu běžný. Úspěšný první nákup znamená 110 → 90 kreditů a jeden vlastněný předmět, ne pouze animaci.

B — NOMAD Shop Editor

Otevřete Tools > NOMAD > Shop Editor. Úplný přehled polí a postupů popisuje vytvoření/výběr katalogu, přejmenování/pořadí/skrytí/odstranění kategorií, vytvoření/odstranění/přeřazení položek, ID, měnu, zásoby/limity, ikony, prefaby, rámování, jazyky, uložení a validaci. Rozbalte definici (záhlaví s ID, případně Element), lokalizované texty a Preview. Většina polí jsou serializované vlastnosti Unity; neexistuje skrytý návrhář motivů, cenová kalkulačka ani generátor herního vybavení.

C — UI obchodu a interakce

ShopView.Create(parent, font) vytvoří overlay canvas; Open(catalog, backend) zobrazí první viditelnou kategorii. Demo obojí připraví automaticky. Kategorie se posouvají vodorovně, položky svisle. Výběr zobrazí přeložený název/popisek, živý náhled, Stats, cenu dodávky a dostupnost. VŠECHNY PŘEDMĚTY ukazují položky aktuální kategorie; MOJE VÝBAVA filtruje tuto kategorii na vlastněné. Nejde o celý nesouvisející herní inventář. Nedostupné položky zůstávají v seznamu, ale nelze je koupit. Prázdná kategorie má vlastní prázdný stav.

KOUPIT PŘEDMĚT požádá backend o nákup; dole se objeví potvrzení, aktualizuje se zůstatek/vlastnictví a tlačítko respektuje peníze/kapacitu/zásoby/limity. Dodávka stojí Price a přidá Quantity kusů. VYBAVIT PŘEDMĚT samostatně volá adaptér, pokud je Equippable a vlastněný. Mohou se objevit NEDOSTATEK PROSTŘEDKŮ, PLNÝ INVENTÁŘ, UZAMČENO, VYPRODÁNO, JIŽ VLASTNĚNO či NEDOSTUPNÉ. Selhání dodávky se správným adaptérem vrací stav; nejde o platební bránu.

UI kontroluje backend přibližně každých 0,15 s a obnovuje změněné řádky. Není to nástroj živého vytváření katalogu: po strukturálních změnách zavřete a otevřete. ESC/F jsou zkratky NomadDemo; samotný ShopView je nenastavuje. Zavření volá CloseRequested, který host musí propojit se skutečným zavřením/úklidem. Demo řeší pouze viditelnost/zamčení kurzoru. Detekce NPC, akce interakce, potlačení vstupů, zaměřovač a pauza patří integraci. Použijte návod API a postup vstupů; nenechávejte za obchodem přímé čtení pohybu/střelby.

D — 3D prohlížeč předmětů

Do Preview přiřaďte Project prefab; první bezpečný test je Assets/NomadShop/Demos/Prefabs/Nomad_FieldFlask.prefab. Použijte MeshRenderer s platným meshem/materiály nebo SkinnedMeshRenderer. Transformace modelu aplikujte a pivot připravte v modelovacím nástroji; herní prefab zachovejte a pro viewer upravte Preview.Rotation/Scale. Doporučujeme jednoduchý preview prefab pouze s vykreslováním, přestože herní skripty se nespouštějí.

Zdroj se nikdy neinstancuje. Core kopíruje mesh/materiály; skinned mesh zapeče v dodané póze. Nepřehrává animace a nekopíruje collidery, rigidbody, zbraně, částice, skripty ani zvuk. Čistě částicový prefab nemá kompatibilní model; použije se přiřazená Icon. Vypnuté renderery/neaktivní vykreslované objekty mohou být vynechány. Nepodporované materiály zůstanou nepodporované: izolace nepřevádí pipeline ani nespouští generování meshů skriptem.

Ortografická Preview Camera a tři světla typu spot bez stínů jsou na vzdálené platformě v samostatné scéně s lokální fyzikou. RenderTexture 1024×528 (výchozí 2× AA) vykresluje do RawImage přijímajícího raycasty. Catalog.PreviewLayer nesmí používat gameplay; existující herní kamery získají dočasné vyloučení vrstvy a při zavření je uvolní se zachováním ostatních bitů. Nové kamery vzniklé až po otevření musí rezervovanou vrstvu respektovat ve vaší integraci. Neměňte kvůli náhledu globální kolizní vrstvy.

Bounds se normalizují a rámují podle projekce: skutečné rozměry zdroje neurčují přímo velikost zobrazení. Preview.Scale je relativní vyplnění (0,2–1), CameraSize minimum rámu, TargetOffset omezený posun cíle a Rotation Eulerovy stupně. Kamera se zvětší proti ořezu a plynule zmenšuje rám. Viz rozsahy a jednotky. U modelu na boku nejprve mimo Play upravte Rotation, ne herní prefab; začněte Y=25 a X/Z měňte jen podle potřeby.

Držte levé tlačítko nad obrázkem a táhněte vodorovně pro yaw, svisle pro pitch (±65°). Po uvolnění se pohled drží 1,75 s a pak z aktuálního natočení pokračuje automatické otáčení. Kolečko mění omezený zoom; RESET POHLEDU vrátí počáteční yaw/pitch/zoom, nemění katalog. AutoRotateSpeed 0 vypne automatiku. ResumeDelay, DragSensitivity a TextureWidth/Height jsou runtime pole/API komponenty, ne zvláštní ovládání katalogu; vlastní kód je může nastavit před vytvořením dalšího náhledu. Přepnutí jazyka zachová model/RenderTexture i natočení.

Chybí model: prověřte Preview.Prefab, zapnuté kompatibilní meshe, materiály, Icon a Preview.LastError. Zavření uvolní RT/model a vypne preview kameru/světla; zničení view odpojí preview scénu. Nejde o živou simulaci zbraně. Viz řešení problémů.

E — Integrace měny a inventáře

Integrace obsahuje přesné smlouvy IShopBackend/IShopWallet/IShopInventory/IShopPurchaseRule, ukázky v licencovaném balíčku, ověřování transakcí, omezení rollbacku, ID požadavků, vlastnictví služby a ukládání. Shodné CurrencyID a skutečný Count inventáře jsou povinné. Demo se po Play resetuje; není trvalým inventářem hry. Metadata bez adaptéru skutečné zbraně nedoručují.

F — Lokalizace

Obsahové texty (Title, Vendor, Currency; Name kategorie; Name, Description, Requirements předmětu; Label statistiky) jsou LocalizedText. Rozbalte pole v editoru. Kód en znamená angličtinu, cs češtinu. Runtime tlačítko střídá catalog.Languages podle pořadí. Pro NomadDemo nastavte catalog.DefaultLanguage, pro vlastní host view.Language před Open / view.SetLanguage(code) během relace. Přepínač českého editoru mění pouze jeho popisky. Jazyk nemění model náhledu.

Pro fráze UI vyberte v Project/Inspector Assets/NomadShop/Demos/NomadUILocalization.asset. Rozbalte Messages, Text jednotlivých prvků a jazyky. ID ponechte přesně včetně mezer: jsou to anglické klíče vět, nikoli kódy výsledků nákupu. Například ID BUY ITEM má EN/CZ hodnoty; Purchase completed. Item delivered. dodává potvrzení. Vlastní tabulku vytvořte přes Tools > NOMAD > Create UI Localization, uložte mimo dodané demo a přiřaďte do catalog.Localization.

Pro třetí jazyk přidejte de do catalog.Languages a přes + Add language / Přidat jazyk do každého obsahového pole i Text v UI tabulce; nový kód xx změňte na de a napište překlad. Kódy musí být jedinečné a přesné; přeložte všech 27 UI záznamů i obsah. Případně nastavte DefaultLanguage de a vyzkoušejte celé rozhraní. Tlačítko ukazuje velká písmena kódů (CZ pro cs); není databází názvů jazyků. Čísla/statistiky se automaticky kulturně neformátují.

Fallback: chybějící/prázdná hodnota zvoleného jazyka použije anglický záznam, ne další jazyk či DefaultLanguage. Pokud chybí i angličtina, vrátí prázdný text. Chybějící UI ID/tabulka používá vestavěné EN/CZ; existující fráze bez třetího překladu použije vlastní anglický záznam. Angličtinu udržujte úplnou. Duplicitní jazyky používají první shodu a validace je neodhaluje. Chybějící znaky řešte fontem s odpovídající licencí.

G — Přizpůsobení a více obchodů

Bez kódu: katalogy, názvy/pořadí/viditelnost kategorií, texty, ceny, množství, limity/zásoby, ikony, statistiky a prefab/rámování/rotace/zoom náhledu. Pro obchodníky použijte rozdílné katalogy. Jeden katalog má jeden klíč měny; zobrazovaný text je oddělený od identifikátoru peněženky. Více měn vyžaduje odpovídající směrování wallet/backendu, ne pouze přejmenování.

S kódem: barvy/rozložení jsou v ShopView.Build a pomocných metodách/konstantách; tato verze nemá bezkódový editor motivu/rozložení. Udržujte vlastní úpravu zdroje nebo vlastní view nad IShopBackend. ShopView.Create(parent, licensedFont) umožní při vytvoření vlastní typografii; výchozí je vestavěný Unity LegacyRuntime.ttf, ne přibalený cizí font. Delší překlady/seznamy statistik mohou potřebovat úpravu layoutu. Otestujte zamýšlená rozlišení a jazyky.

Integraci vyžadují skutečné doručení/vybavení, odemčení, NPC terminály, vstupy/pauza, save/load, sdílení služby mezi obchodníky a online autorita. Vrstvu náhledu rezervujte jednotně. Dva nezávislé pohledy mohou běžet současně; cena RT/světel roste s viditelnými viewery. Pro sdílené prostředky používejte stejný backend a pro historii obchodníků odlišná ID katalogů. Uložení samotné peněženky nezachová zásoby/historii.

H — Řešení problémů a podklady podpory

Řešení problémů spojuje příznaky s přesnými kontrolami. Nejprve reprodukujte v kopii samostatného dema, teprve pak v herním adaptéru. Zaznamenejte verze Unity/balíčků, validační chyby, ID položky, kód backendu a Preview.LastError. Do podpory neposílejte hesla, identifikátory účtů ani nesouvisející herní assety.
